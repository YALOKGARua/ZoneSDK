# ZoneSDK - ReShade add-on SDK for S.T.A.L.K.E.R. 2

ZoneSDK — це бібліотека C++ у вихідному коді для тих, хто пише аддони ReShade для S.T.A.L.K.E.R. 2: Серце Чорнобиля. Вона компілюється всередину кожного аддона, тож аддон, зібраний на ній, — це один файл `.addon64`, якому під час роботи більше нічого не потрібно.

**Гравцям ZoneSDK не потрібен.** Якщо ви хочете лише грати з аддоном, зібраним на ньому, встановіть цей аддон і ReShade; цей пакет — для авторів модів.

English: [README.md](README.md).

## Що всередині

- Стартовий аддон (`release\1.0.1\template\ZoneTemplate`), який `new-addon.cmd` копіює у вашу власну теку з новою назвою, тегом, клавішею і смугою підказок.
- Два зразки для читання: `samples\ZoneHelloHud` (панель на екрані з даними від функцій гри, знайдених через рефлексію) і `samples\ZoneFieldWatch` (модель безпеки для читання сирої пам'яті).
- Інструменти, кожен однією командою: `doctor.cmd` перевіряє ПК, `build.cmd` / `test.cmd` збирають і тестують, `fakehost.cmd` запускає аддон без гри, `build.cmd -Verify` перевіряє готовий файл, `pack.cmd` робить архів для гравців.
- Вбудована модель безпеки:
  - виклики гри виконуються лише в потоці гри, через помпу SDK; сторона малювання ніколи не викликає гру;
  - кожен ризикований виклик несе мітку збою: виклик, що одного разу спричинив збій, лишається вимкненим, доки гравець не натисне «Спробувати ще» у блоці «Діагностика» аддона;
  - можливості, що залежать від точних байтів гри, прив'язані до відомих збірок гри і самі вимикаються на збірці, якої SDK не знає;
  - структурований виняток (наприклад, порушення доступу до пам'яті) в одному з ваших хуків на боці ReShade (кадр, оверлей, вкладка, хуки GPU), у фоновому завданні чи в хуках перепису вимикає цю частину аддона і пише один рядок у журнал; ця частина лишається вимкненою, і в наступних сесіях гри теж, доки гравець не натисне «Спробувати ще». Такий виняток у хуку потоку гри зупиняє всі виклики гри до кінця цієї сесії. Винятки C++, як і раніше, перехоплює і записує в журнал внутрішній обробник;
  - налаштування і журнал лежать у `%LOCALAPPDATA%\<тека аддона>`, тексти — українською та англійською.

Живий приклад: аддон A-Life «Пульс Зони / Zone Pulse» (`ZonePulse.addon64`) зібрано на ранішій версії ZoneSDK: https://www.nexusmods.com/stalker2heartofchornobyl/mods/3021

## Вимоги

Щоб збирати аддони:

- Windows 10 або Windows 11, 64-бітна.
- Visual Studio 2022 версії 17.10 або новішої чи Visual Studio 2026. Досить безкоштовних Build Tools. Потрібні робоче навантаження «Desktop development with C++» (інструменти MSVC x64) і Windows 11 SDK. Як їх встановити, показано в [docs/GETTING_STARTED-UA.md](docs/GETTING_STARTED-UA.md).
- Windows PowerShell 5.1, який є в кожній Windows 10 і 11. Запускачі `.cmd` завжди використовують саме його.
- Python 3 — за бажанням. Якщо Python встановлено, `build.cmd -Verify` читає ним готовий файл, а без нього обходиться PowerShell.

Щоб запускати аддони в грі:

- S.T.A.L.K.E.R. 2: Серце Чорнобиля, **версія для Steam**. ZoneSDK 1.0.1 знає дві збірки гри: `2bd3f115` — версія гри 2.1 «The Zone Lookout» (збірка Steam 26123434, вийшла 26 жовтня 2026 року; її exe датований 21 жовтня 2026 року) і `61bc1e03` — версія гри 2.0.6 (Steam, exe датований 18 вересня 2026 року), яка лишається відомою. Інші видання не підтримуються. На збірці Game Pass аддон завантажується, пише «Ця версія гри не підтримується» і нічого не змінює. На збірці гри, якої ZoneSDK не знає, наприклад після оновлення гри, функції, прив'язані до відомої збірки, лишаються вимкненими, доки ZoneSDK не дізнається нову; див. [docs/PATCH_DAY-UA.md](docs/PATCH_DAY-UA.md).
- ReShade 6.8 або новіший, варіант завантаження **with full add-on support** (API аддонів 20), встановлений для гри з DirectX 12.

### З чим перевірено

ZoneSDK 1.0.1 перевірено з MSVC 14.44 (набір інструментів 14.44.35207, Visual Studio 2022 Build Tools) і Windows SDK 10.0.26100.0, у Windows 11 з Windows PowerShell 5.1 і ReShade 6.8.0. Visual Studio 2026 та інші версії MSVC з підтримуваного діапазону приймаються, але не перевірялися. Якщо новіший компілятор видає попередження у файлі ZoneSDK, збирання пише `sdk warnings N (compiler newer than tested)` і йде далі; попередження у вашому власному коді, як і раніше, зупиняють збирання.

## Як ZoneSDK знаходить інструменти збирання

Кожне збирання шукає інструменти C++ у такому порядку і бере перші, що працюють:

1. `ZSDK_VCVARS`: повний шлях до `vcvars64.bat` або до вашого власного `.bat`, який налаштовує `cl`, `link`, `rc` і `dumpbin`.
2. `_toolchain\vcvars-winsdk.bat` у теці випуску або в будь-якій теці над нею — для інструментів, що лежать поруч із вашими теками SDK.
3. `vswhere`: найновіша встановлена Visual Studio 2022 17.10+ або Visual Studio 2026, у якій є інструменти MSVC x64. Тестові (prerelease) збірки Visual Studio пропускаються.

`ZSDK_VCVARS_VER=14.44` задає певний набір інструментів MSVC (його передають у `vcvars64.bat` як `-vcvars_ver`). Кожне збирання пише, які інструменти взяло, наприклад `toolchain msvc 14.44.35207, windows sdk 10.0.26100.0`, а `doctor.cmd` показує версії `cl`, `link`, `rc` і `dumpbin`.

## Швидкий старт за 5 команд

Спершу розблокуйте архів (див. нижче), потім розпакуйте його в теку для ваших модів; в архіві одна тека, `ZoneSDK-1.0.1`. Відкрийте командний рядок або PowerShell у `ZoneSDK-1.0.1` і виконайте:

```
.\doctor.cmd
.\new-addon.cmd -Name MyHud -Target ..\MyHud -Author "Your Name" -Tag YourNameMyHud
..\MyHud\build.cmd -Tests -Verify
.\fakehost.cmd -Addon ..\MyHud\bin\MyHud.addon64 -All
..\MyHud\pack.cmd
```

1. `doctor` перевіряє PowerShell, інструменти збирання, Python, теку гри, ReShade і збірку гри. Він нічого не змінює, лише читає.
2. `new-addon` робить зі стартового аддона ваш власний аддон `MyHud` поруч із текою SDK. Виберіть тег, якого більше ніхто не використовує: найпростіше поставити на початок своє авторське ім'я.
3. `build -Tests -Verify` збирає `MyHud\bin\MyHud.addon64`, проганяє його набори тестів і перевірки готового файлу.
4. `fakehost -All` завантажує аддон у несправжній хост (fake host), що вдає процес гри, і проводить його через запуск, вихід, примусове завершення і збій — без гри. Наприкінці він пише `fake host modes: N checks, 0 failures, M skipped`.
5. `pack` пише `MyHud\dist\MyHud-0.1.0.zip` для гравців.

Кожен крок пояснено в [docs/GETTING_STARTED-UA.md](docs/GETTING_STARTED-UA.md), разом із тим, як випробувати аддон у грі.

Нічого не змінюйте в `release\1.0.1`: кожне збирання звіряє випуск із його `MANIFEST.sha256` і зупиняється, якщо якийсь файл змінено. Стартовий аддон теж не можна зібрати на місці; `new-addon.cmd` робить вашу власну копію.

### Де живе ваш аддон і що таке ZSDK_ROOT

Ваш аддон — це окрема тека поза `release\`. Його `build\zsdk.lock` закріплює версію ZoneSDK і маніфест випуску, з яким його створено, тож аддон збирається саме з цим випуском, доки ви не перенесете його на іншу версію ZoneSDK. Збирання шукає випуск у такому порядку:

1. `ZSDK_ROOT`: розпакована тека ZoneSDK, та, у якій лежить `release\1.0.1`;
2. `home=` у `build\zsdk.lock`: шлях відносно теки аддона. `new-addon` пише його, коли аддон не знаходить випуск сам, наприклад `home=..\ZoneSDK-1.0.1`;
3. прохід угору батьківськими теками аддона в пошуках `release\1.0.1` або `_sdk\release\1.0.1`.

Випуск з іншим маніфестом пропускається. Якщо нічого не підходить, помилка перелічує всі місця, де відбувався пошук. `build.cmd -Where` показує випуск, який буде взято, нічого не збираючи.

Якщо аддон лежить на іншому диску, ніж SDK, задайте `ZSDK_ROOT` перед збиранням. У командному рядку: `set "ZSDK_ROOT=<тека>\ZoneSDK-1.0.1"`; у PowerShell: `$env:ZSDK_ROOT = '<тека>\ZoneSDK-1.0.1'`. Обидва варіанти діють, доки ви не закриєте вікно.

## Завантажений архів: Unblock-File і політика виконання

Windows позначає файли з Інтернету (Mark-of-the-Web). Зніміть цю позначку до розпакування: клацніть архів правою кнопкою, виберіть «Властивості», установіть прапорець **Розблокувати** і натисніть «OK». Або в PowerShell, у теці з архівом:

```
Unblock-File -LiteralPath .\ZoneSDK-1.0.1.zip
```

Якщо ви вже розпакували архів, виконайте в PowerShell усередині `ZoneSDK-1.0.1`:

```
Get-ChildItem -LiteralPath . -Recurse | Unblock-File
```

Користуйтеся запускачами `.cmd`: `doctor.cmd`, `new-addon.cmd` і `fakehost.cmd` у теці пакета, `build.cmd`, `test.cmd` і `pack.cmd` у теці кожного аддона. Кожен із них запускає Windows PowerShell з `-ExecutionPolicy Bypass` лише для свого сценарію, тому працює з типовою політикою і з позначеними файлами та не змінює жодних налаштувань. Файл `.ps1`, запущений напряму, типова політика відхиляє («running scripts is disabled on this system»), а позначений — ще й політика RemoteSigned («is not digitally signed»). Якщо ви хочете запускати файли `.ps1` самі, розблокуйте файли і дозвольте локальні сценарії для свого користувача командою `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Якщо групова політика примусово задає Restricted або AllSigned, обійти її неможливо; `doctor.cmd` про це скаже.

Запущений подвійним клацанням у Провіднику, запускач наприкінці чекає натискання клавіші, щоб ви встигли прочитати вивід. `ZSDK_NOPAUSE=1` вимикає це.

## Кілька аддонів на різних версіях ZoneSDK

Кожен аддон несе власну копію ZoneSDK усередині свого `.addon64`; спільної DLL немає. Тому аддони, зібрані на різних версіях ZoneSDK, працюють поруч в одній грі, а оновлення одного аддона ніколи не зачіпає інший.

Між аддонами обов'язково має відрізнятися **тег**. Він дає ім'я м'ютексу, який не пускає другу копію аддона, і повідомленню аддона для потоку гри. Якщо два аддони в одній грі мають один тег, другий мовчки не завантажується; він лише пише у вивід налагодження Windows рядок `ZoneSDK: <name> does not load: the tag <tag> is already taken ...`, який показує переглядач на кшталт DebugView. `new-addon.cmd` бере тег з `-Tag` (або з назви), відхиляє теги, які вже використовує власна таблиця ZoneSDK, зразок або аддон поруч із цільовою текою, і радить ставити на початок своє авторське ім'я. Теку налаштувань, клавішу і смугу підказок теж бажано зробити різними; `new-addon.cmd` вибирає клавішу і смугу, яких не використовують таблиця, зразки й аддони поруч із цільовою текою, і попереджає, що в гравця може бути інший аддон, який їх уже використовує. Набір тестів identity теж попереджає, якщо аддон у сусідній теці має ту саму смугу підказок чи типову клавішу.

## Маніфест випуску

Кожну теку випуску закріплює її `MANIFEST.sha256`. SHA-256 файлу `release\1.0.1\MANIFEST.sha256` у цьому пакеті:

```
A21B6E436296519498775ED30DFD9F0AA616E1402A488199E20F9A9DC7E2D1CF
```

Щоб перевірити, виконайте `Get-FileHash -LiteralPath .\release\1.0.1\MANIFEST.sha256` у PowerShell у теці пакета. Збирання пише перші 8 символів (`zsdk 1.0.1 manifest XXXXXXXX`), і кожен аддон під час запуску пише те саме у свій журнал, тож дві копії однієї версії можна розрізнити.

## Плани (дорожня карта)

Що буде після 1.0.1, у такому порядку. Дат немає: кожен крок виходить, коли він готовий і перевірений.

- **1.1**
  - Безпечний виклик «сирих» нативних функцій гри через один спільний вхід, з журналом збоїв і кнопкою «Спробувати ще».
  - Спільна «книга фактів про гру» і читабельні описи ігрових класів, щоб після оновлення гри виправляти все в одному місці.
  - Інструмент, який після оновлення гри сам знаходить нові адреси, і повний перелік функцій гри.
- **1.2**
  - «Чорна скринька»: після вильоту видно, який аддон що робив, а повторний виліт на тому самому кроці сам вимикає цю частину.
  - Знання про збереження гри: дані окремо для кожного збереження і журнал для гравця.
  - Новий «перепис» NPC і мутантів, спільний для всіх аддонів.
  - Набір «несправжньої гри» для тестів аддонів без запуску гри.
- **1.3**
  - Об'єкти й ефекти у світі без підвисань, з безпечним видаленням, трасуванням променів і прикріпленням.
  - Після збою SDK повертає гравцеві керування, камеру та все інше, що «тримав» аддон.
- **1.4 і далі**
  - Спільні безпечні модулі для посадки гравця, власної камери, телепорту і керування NPC — для «транспортних» модів.
  - Зручності для великих аддонів: сховище JSON, підвантаження частин рівня, навігація, мапа КПК і вікна гри.

Пізніші ідеї, ще не заплановані: підтримка інших видань гри (Game Pass) і помічник на день оновлення гри, який із нового файлу гри робить готовий опис збірки для вашого аддона.
