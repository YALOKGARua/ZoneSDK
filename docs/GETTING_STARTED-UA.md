# Перші кроки з ZoneSDK

Цей посібник веде від ПК без інструментів збирання до вашого власного аддона, що працює в S.T.A.L.K.E.R. 2. Першого разу пройдіть його від початку до кінця. Кожну команду з кроків 2–8 виконано на свіжій копії пакета.

English: [GETTING_STARTED.md](GETTING_STARTED.md).

У прикладах аддон зветься `MyHud`, а теки розкладено так:

```
Mods\
  ZoneSDK-1.0.2\     розпакований пакет
  MyHud\             ваш аддон, створений на кроці 4
```

Команди однаково працюють у командному рядку і в PowerShell. Вводьте їх так, як показано, з `.\` на початку.

## 1. Встановіть інструменти збирання

Потрібна Visual Studio 2022 (17.10 або новіша) чи Visual Studio 2026 з інструментами C++. Досить безкоштовних **Build Tools**; повна Visual Studio (Community, Professional) теж підходить.

1. Завантажте «Build Tools for Visual Studio» зі сторінки завантажень Visual Studio від Microsoft (visualstudio.microsoft.com, розділ «Tools for Visual Studio»).
2. В інсталяторі позначте робоче навантаження **Desktop development with C++**. Залиште складники, які воно вибирає: інструменти збирання MSVC x64 і Windows 11 SDK.
3. Встановіть, а потім відкрийте нове вікно командного рядка.

Через winget те саме встановлення для Visual Studio 2022 — це один рядок:

```
winget install --id Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

ZoneSDK сам знаходить інструменти через `vswhere`. Якщо вони лежать деінде, вкажіть у `ZSDK_VCVARS` шлях до їхнього `vcvars64.bat` (див. «Як ZoneSDK знаходить інструменти збирання» у [README-UA](../README-UA.md)).

За бажанням:

- Python 3 (з python.org). `build.cmd -Verify` читає ним готовий файл, а без нього обходиться PowerShell. `ZSDK_PYTHON` може вказувати на `python.exe`, а `ZSDK_PYTHON=none` вимикає Python. Збирання шукає `python.exe` у `PATH`, а не запускач `py`: якщо doctor показує лише `py.exe`, задайте в `ZSDK_PYTHON` повний шлях до вашого `python.exe`.

Для перевірки в грі (крок 9) потрібні ще версія гри для Steam і ReShade 6.8 або новіший, варіант завантаження **with full add-on support**. Запустіть інсталятор ReShade, виберіть `Stalker2-Win64-Shipping.exe` у `<тека гри>\Stalker2\Binaries\Win64` і вкажіть Direct3D 10/11/12.

## 2. Розпакуйте і розблокуйте

Windows позначає завантажені файли (Mark-of-the-Web). Зніміть позначку з архіву **до** розпакування: клацніть архів правою кнопкою, «Властивості», установіть прапорець **Розблокувати** і натисніть «OK». Або в PowerShell, у теці з архівом:

```
Unblock-File -LiteralPath .\ZoneSDK-1.0.2.zip
```

Потім розпакуйте архів у `Mods`. В архіві одна тека, `ZoneSDK-1.0.2`.

Уже розпакували, не розблокувавши? Виконайте в PowerShell усередині `ZoneSDK-1.0.2`:

```
Get-ChildItem -LiteralPath . -Recurse | Unblock-File
```

Запускачі `.cmd` працюють навіть із позначеними файлами, бо кожен запускає свій сценарій з `-ExecutionPolicy Bypass`. Розблокування важливе тоді, коли ви запускаєте `.ps1` самі.

## 3. Перевірте ПК: doctor

Відкрийте вікно командного рядка в `Mods\ZoneSDK-1.0.2` і виконайте:

```
.\doctor.cmd
```

Він лише читає і пише по рядку на кожну перевірку: `ok`, `warn`, `info` або `FAIL`. На справному ПК головні рядки мають такий вигляд:

```
ok    toolchain wrapper ...\VC\Auxiliary\Build\vcvars64.bat
ok    cl.exe 14.44.35228.0 at ...
ok    Windows SDK 10.0.26100.0, MSVC tools 14.44.35207
ok    game folder ... (Steam libraryfolders.vdf, 2 libraries)
ok    ReShade 6.8.0 (dxgi.dll), add-on loader present; ...
ok    game build 2bd3f115 (2026-10-21) is known to ZoneSDK 1.0.2
doctor: 0 problems, 1 warnings
```

Дата в дужках — це дата збірки, записана в exe гри, а не день, коли оновлення вийшло в Steam. Якщо хоч один рядок `FAIL`, він завершується з кодом 1. Попередження `warn` про політику виконання означає лише те, що звичайний `.ps1` не запуститься; запускачі все одно працюють. Корисні параметри:

- `.\doctor.cmd -Game "<тека гри>"`, коли Steam не знаходить гру (це тека, у якій лежить `Stalker2`);
- `.\doctor.cmd -Addon MyHud`, коли ваш аддон уже побував у грі: чи не вимкнено його в `ReShade.ini` і чи завантажив його ReShade минулого разу;
- `.\doctor.cmd -Selftest` додатково запускає власну самоперевірку шаблону ZoneSDK (check-scaffold) усередині пакета. Вона триває близько семи хвилин і для звичайної роботи не потрібна. Під час роботи вона виводить рядки `FAIL` від випадків, які мають провалитися; підсумок — рядок `ok    self-test: check-scaffold passed inside the release`. Вона працює в новій теці в `%TEMP%` і видаляє її після успіху; після провалу тека лишається, і самоперевірка називає її.

Для збирання аддонів сама гра не потрібна: без неї doctor попереджає і йде далі. Коли гра є, але ReShade для неї ще не встановлено, doctor показує один рядок `FAIL` про ReShade і завершується з кодом 1; збирання, тести і несправжній хост працюють і без ReShade. Кожен запускач (`doctor`, `new-addon`, `build`, `test`, `pack`, `fakehost`) виводить свої параметри з `-Help` або `-?`.

## 4. Створіть свій аддон: new-addon

```
.\new-addon.cmd -Name MyHud -Target ..\MyHud -Author "Your Name" -Tag YourNameMyHud
```

Команда копіює стартовий аддон у `Mods\MyHud`, перейменовує все всередині і пише, що вибрала:

```
created MyHud in ...\Mods\MyHud
  define MYHUD, namespace zmyhud, header src\myhud.h
  tag YourNameMyHud, toast lane 0.72 (picked: ...), key ALT+H (picked: ...)
  ZoneSDK 1.0.2 manifest XXXXXXXX from ...\release\1.0.2 pinned in build\zsdk.lock, home=..\ZoneSDK-1.0.2
```

Параметри:

| Параметр | Що робить |
| --- | --- |
| `-Name` | Назва аддона: від 2 до 40 латинських літер і цифр, першою має бути літера. Префікс `Zone` — лише звичка, а не правило. Назви зі словом `template` відхиляються. |
| `-Target` | Нова тека. Такої теки ще не має бути, і вона має лежати поза `release\`. |
| `-Author` | Ваше ім'я, яке потрапить у ресурс версії файлу: його показує ReShade, і його потребує `pack`. Латинські літери, цифри, пробіли і `. , _ & ( ) ' + -`; ім'я кирилицею відхиляється, тож тут запишіть його латинкою, а написання кирилицею залиште для сторінки мода. |
| `-Tag` | Тег, див. нижче. Типово — назва. |
| `-Key` | Типова клавіша, наприклад `ALT+K` або `CTRL+SHIFT+F7`. Типово — вільне сполучення з ALT з таблиці ZoneSDK. Клавіші цифрового блока відхиляються, бо на багатьох клавіатурах його немає. |
| `-Lane` | Місце на екрані, де з'являються підказки аддона, як частка висоти екрана від 0 до 0.95; 0 означає без підказок. Типово — вільна смуга з таблиці ZoneSDK. |
| `-Define` | Префікс макросів C++ аддона. Типово — назва великими літерами без `Zone`, тут `MYHUD`. |
| `-Release` | Інша розпакована тека випуску, до якої треба прив'язати аддон. Типово — випуск, з якого запущено `new-addon`. |

**Тег має бути унікальним** серед усіх аддонів ReShade, які є в гравця. Він дає ім'я м'ютексу, який не пускає другу копію аддона, і повідомленню аддона для потоку гри. Якщо два аддони в одній грі мають один тег, другий мовчки не завантажується. Ставте на початок своє авторське ім'я, як у `YourNameMyHud`. `new-addon` відхиляє назву чи тег, які вже використовує власна таблиця ZoneSDK або один зі зразків, а також тег аддона з теки поруч із цільовою. Він вибирає клавішу і смугу, яких не використовують таблиця, зразки й аддони поруч із цільовою текою, і попереджає, що їх усе ж може використовувати аддон, якого він не бачить. Якщо задана вами `-Key` чи `-Lane` вже зайнята кимось із них, теж буде попередження.

Що з'явиться в `Mods\MyHud`: `src\` (ваш код), `tests\` (ваші тести і `tests\zsdk.cfg`), `build\make.ps1`, `build\pack.ps1`, `build\zsdk.lock`, `dist\README-EN.txt` і `dist\README-UA.txt` (описи для гравців), запускачі `build.cmd`, `test.cmd` і `pack.cmd`, а також `.gitignore`, який не пускає в git результати збирання й архіви. Наприкінці `new-addon` виводить свої наступні кроки. Два з них відрізняються від кроків нижче: його крок 3 — один запуск несправжнього хоста без `-All` (крок 6 тут проганяє всі режими), а його крок 4 — простий `.\build.cmd -Verify`, після якого `pack` попереджає; натомість виконуйте `.\build.cmd -Tests -Verify` (крок 7).

`build\zsdk.lock` закріплює ZoneSDK 1.0.2 і його маніфест. Рядок `home=..\ZoneSDK-1.0.2` у ньому підказує збиранню, де лежить випуск. Якщо ви перенесете аддон на інший диск, задайте натомість `ZSDK_ROOT` — теку ZoneSDK (див. [README-UA](../README-UA.md)).

Стартовий аддон дозволяє коментарі у вашому коді. Якщо ви хочете, щоб тести їх забороняли, додайте рядок `comments=forbid` у `tests\zsdk.cfg`.

## 5. Зберіть і протестуйте

```
cd ..\MyHud
.\build.cmd -Tests
```

`.\test.cmd` робить те саме. Перше збирання триває приблизно хвилину. Кінець вдалого збирання:

```
tests passed 9 failed 0 checks 1081, 2 test warnings
sdk warnings 0
warnings 0
```

- Аддон — це `bin\MyHud.addon64`; повний журнал — `build\last-build.log`.
- Два попередження тестів для нового аддона звичайні: набір тестів guards не мав файлу гри для порівняння, а вашого аддона немає в таблиці ZoneSDK, тож використано його власний рядок.
- Попередження у вашому власному коді зупиняють збирання: дозволено 0.
- Якщо тест провалюється, збирання видаляє `bin\MyHud.addon64` і його pdb, тож провалену збірку не можна ні запакувати, ні встановити. Збирання з тестами, які пройшли, пише `bin\MyHud.tested`, а `pack` попереджає, якщо файл, який він пакує, зібрано без успішних тестів. Кожне збирання спершу прибирає цю позначку, тож пізніше збирання без `-Tests` (наприклад, просто `.\build.cmd -Verify`) змусить `pack` попередити: останнім перед пакуванням збирайте з `-Tests`.
- `.\build.cmd -Tests -Exe "<тека гри>\Stalker2\Binaries\Win64\Stalker2-Win64-Shipping.exe"` або `-LiveExe` (встановлена гра, яку знайдено через Steam) дає набору тестів guards звірити ваші перевірки байтів зі справжнім файлом гри. Файл лише читається.
- `.\build.cmd -Config Debug` пише налагоджувальну збірку в `bin\Debug\`. Ніколи не випускайте її: `pack` бере лише `bin\MyHud.addon64`, а `-Verify` відхиляє налагоджувальну збірку.
- `.\build.cmd -Where` показує, який випуск ZoneSDK бере аддон, нічого не збираючи: теку випуску, як її знайдено, версію, маніфест і файл закріплення.
- Два збирання одного аддона ніколи не йдуть одночасно: друге чекає на перше (воно тримає `build\.zsdk-build.lock`) до 30 хвилин.

## 6. Запустіть без гри: fakehost

```
..\ZoneSDK-1.0.2\fakehost.cmd -Addon bin\MyHud.addon64 -All
```

Несправжній хост (fake host) — невелика програма з тією самою назвою, що й файл гри. Він завантажує ваш `.addon64` так, як це робить ReShade, виводить кадри, відкриває оверлей і вкладку і завершує процес по-різному: звичайний вихід, примусове завершення, вихід посеред малювання, вихід з іншого потоку, збій і повідомлення про вихід. Після кожного прогону він перевіряє аддон. Першого разу він збирає сам себе, це забирає кілька секунд. Повний прогін триває близько трьох хвилин і закінчується так:

```
fake host modes: 116 checks, 0 failures, 35 skipped
```

Пропущені 35 перевірок (групи `gpu`, `job`, `seh`, `report` і `quit`) потребують власного тестового аддона ZoneSDK для збоїв, який навмисно все ламає і в пакет не входить; `-Expect` вмикає їх для нього, а всі інші аддони їх пропускають. Код виходу — це кількість провалів. Журнал, налаштування і результат кожного прогону лежать у `%LOCALAPPDATA%\ZoneSDK\1.0.2\fakehost\harness\MyHud`, а `summary.txt` перелічує всі перевірки.

Несправжній хост ніколи не запускається, поки працює гра або інший несправжній хост. Без `-All` він робить один звичайний прогін; `new-addon` виводить цю команду з `-Label` і `-Out`, якщо вам потрібен лише один журнал, щоб подивитися.

## 7. Перевірте готовий файл: -Verify

```
.\build.cmd -Tests -Verify
```

Команда збирає наново, запускає тести, а потім перевіряє файл, який отримають гравці:

- він експортує рівно `NAME` і `DESCRIPTION`, як очікує ReShade;
- у нього є ресурс версії, і це не налагоджувальна збірка (немає прапорця Debug і налагоджувальної бібліотеки виконання, Debug CRT);
- у його байтах немає жодної вашої теки: ні теки аддона, ні теки ZoneSDK, ні теки користувача чи шляху з вашим іменем користувача Windows, ні іншого абсолютного шляху з літерою диска;
- один прогін несправжнього хоста: жодного виклику ImGui поза оверлеєм, друга копія відхиляється, вкладка малюється.

Наприкінці з'являється `verify: passed (fake host, exports, version resource, byte scan)`. `.\build.cmd -Verify` без `-Tests` перевіряє те саме, але лишає збірку, про яку `pack` попередить (крок 5).

## 8. Запакуйте архів для гравців

1. Задайте свою версію в `src\version.h` (`MYHUD_VERSION_MAJOR`, `_MINOR`, `_PATCH`) і зберіть наново командою `.\build.cmd -Tests`. Версію, яку ви випускаєте, збирайте командою `.\build.cmd -KeepSymbols`: вона робить перевірену тестами збірку Release і зберігає файл аддона, його pdb, файл закріплення, журнал збирання і zip із вашим вихідним кодом у `dist\<версія>\symbols`, де їх ніколи не перезаписують. Кожне наступне збирання замінює `bin\MyHud.pdb`, а налагоджувачу потрібен pdb саме випущеного файлу, щоб перетворити `MyHud.addon64+0x...` з рядка журналу на функцію і рядок коду.
2. Відредагуйте `dist\README-EN.txt` і `dist\README-UA.txt`: вони потрапляють в архів для гравців. `pack` сам підставляє `{{VERSION}}`, `{{AUTHOR}}`, `{{GAME}}` і `{{ZSDK}}`.
3. Запакуйте:

```
.\pack.cmd
```

Команда пише `dist\MyHud-0.1.0.zip` і `dist\MyHud-0.1.0-SHA256.txt`. В архіві:

```
NOTICE-ADDON.txt
README-EN.txt
README-UA.txt
SHA256.txt
Stalker2/Binaries/Win64/MyHud.addon64
```

Гравці (і менеджери модів) розпаковують його в теку гри. Та сама збірка, запакована двічі, дає той самий архів. `pack` бере лише збірку Release, відхиляє файл із прапорцем Debug і попереджає, якщо якийсь файл коду новіший за збірку або якщо збірка не пройшла тести; `.\pack.cmd -Build` спершу збирає і тестує.

`NOTICE-ADDON.txt` містить ліцензії ZoneSDK і заголовків, що потрапили у ваш аддон. Якщо пакуєте вручну, скопіюйте у свій архів `release\1.0.2\NOTICE-ADDON.txt` з теки ZoneSDK.

## 9. Випробуйте в грі

У ZoneSDK 1.0.2 немає інсталятора, тож файл копіюється вручну:

1. Закрийте гру.
2. Скопіюйте `bin\MyHud.addon64` у `<тека гри>\Stalker2\Binaries\Win64`, поруч із `dxgi.dll` від ReShade. Або розпакуйте свій архів у теку гри, ту, у якій лежить `Stalker2`.
3. Запустіть гру і натисніть **Home**, щоб відкрити ReShade. В аддона є власна вкладка з його назвою, `MyHud`. Вкладка **Add-ons** теж показує його і може його вимкнути.
4. Завантажте збереження і натисніть клавішу аддона (у цьому прикладі `ALT+H`; вкладка показує її і дає змінити). Стартовий аддон показує, де ви стоїте.

Наприкінці вкладки є блок **Діагностика**: збірка гри (відома, інша чи не Steam-версія), скільки функцій гри знайдено, виклики, вимкнені після збою, кнопки **Спробувати ще** і **Скопіювати звіт**. Коли щось не працює, дивіться спершу сюди.

## 10. Журнали і налаштування

Кожен аддон тримає свої файли в `%LOCALAPPDATA%\<його тека>`, для `MyHud` — у `%LOCALAPPDATA%\MyHud`:

| Файл | Що в ньому |
| --- | --- |
| `myhud.ini` | Налаштування, клавіша і списки безпеки (виклики, вимкнені після збою). |
| `myhud.log` | Журнал. Кожна сесія гри дописує свої рядки в кінець; перші рядки сесії називають аддон, мову і `zsdk 1.0.2 manifest XXXXXXXX`. |
| `myhud.1.log` | Старіша частина журналу, яку відкладено, коли журнал переріс 4 МБ під час запуску гри (8 МБ під час гри). |
| `myhud.exit` | Мітка чистого виходу, яка пишеться, коли гра закривається звичайним чином. |
| `report.txt` | Його пише кнопка **Скопіювати звіт**, яка також кладе той самий текст у буфер обміну. Імена користувачів і особисті шляхи в ньому приховано. |

ReShade пише власні `ReShade.log` і `ReShade.ini` у `<тека гри>\Stalker2\Binaries\Win64`.

Спершу мова стоїть на `auto`: якщо гра українською, тексти українські, за будь-якої іншої мови гри — англійські. У вкладці мову можна перемкнути на `uk` або `en`.

## 11. Видалення

- Аддон: видаліть `<тека гри>\Stalker2\Binaries\Win64\MyHud.addon64`. Щоб прибрати також його налаштування і журнали, видаліть `%LOCALAPPDATA%\MyHud`.
- ZoneSDK: видаліть теку `ZoneSDK-1.0.2`. У `%LOCALAPPDATA%\ZoneSDK` лежать лише робочі теки несправжнього хоста і тестів; її можна видалити будь-коли, вона з'явиться знову, коли знадобиться. `doctor -Selftest` видаляє свою теку `%TEMP%\zsdk-scaffold-...` після успіху; теку, яка лишилася після провалу, можна видалити вручну.

## 12. Поширені помилки

| Що ви бачите | Що робити |
| --- | --- |
| `... cannot be loaded because running scripts is disabled on this system` | Ви запустили `.ps1` напряму. Скористайтеся запускачем `.cmd` або дозвольте локальні сценарії командою `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. |
| `... is not digitally signed. You cannot run this script on the current system.` | Файл досі має позначку Mark-of-the-Web. Розблокуйте його (крок 2) або скористайтеся запускачем `.cmd`. |
| doctor: `A Group Policy forces Restricted` (або AllSigned) | Жоден інструмент ZoneSDK не обійде групову політику; зверніться до адміністратора ПК. |
| `no C++ toolchain was found. ...` | Встановіть Build Tools (крок 1) або задайте в `ZSDK_VCVARS` шлях до свого `vcvars64.bat`. Повідомлення перелічує всі місця, де відбувався пошук. |
| `the MSVC x64 build tools are missing: ...` | В інсталяторі Visual Studio натисніть **Modify** («Змінити») і позначте **Desktop development with C++**. |
| `the Windows SDK is missing: rc.exe does not resolve ...` | В інсталяторі Visual Studio натисніть **Modify**, відкрийте **Individual components** і позначте Windows 11 SDK (перевірено з 10.0.26100). |
| `sdk warnings N (compiler newer than tested)` | Це не помилка: ваш компілятор новіший за той, з яким перевіряли ZoneSDK, і попереджає про файл SDK. Збирання йде далі. |
| `the build has N warnings in add-on code, 0 are allowed` | Виправте попередження у своєму коді; вони є в `build\last-build.log`. |
| `tests failed: N; the binary is removed, so neither pack nor an install can ship it: ...` | Рядки `FAIL` над ним називають набір тестів і перевірку; провалений набір `zsdk-*` ще й вказує на свій опис у [RULES-UA.md, розділ 10](RULES-UA.md#10-загальні-набори-тестів). Виправте код і зберіть наново командою `.\build.cmd -Tests`. |
| `ZoneSDK 1.0.2 with manifest XXXXXXXX was not found for ... Tried: ...` | Аддон не знаходить свій випуск. Задайте `ZSDK_ROOT` — теку ZoneSDK — або впишіть `home=<шлях відносно аддона>` у `build\zsdk.lock`. Якщо випуск знайдено, але він «is another build of 1.0.2», ви розпакували інший пакет, ніж той, з яким створено аддон: візьміть той пакет. |
| `the ZoneSDK snapshot was edited: <file>` (або `... edited: missing <file>`, `... edited: unlisted <file>`) | Якийсь файл у `release\1.0.2` змінено, вилучено чи додано. Розпакуйте пакет наново; випуск ніколи не редагують. |
| `this add-on folder lies inside the ZoneSDK release ...` | Стартовий аддон не можна зібрати на місці. Створіть власний аддон через `new-addon.cmd`. |
| `the target exists and is never overwritten` | `new-addon` потребує нової теки: виберіть інший `-Target`. |
| `the tag ... is taken in the ZoneSDK registry table` | Виберіть інший `-Tag`, найкраще зі своїм авторським ім'ям на початку. |
| doctor: `ReShade ... is older than 6.8`, `has no add-on loader` або `ReShade is not installed` | Встановіть ReShade 6.8 або новіший, варіант **with full add-on support**, для гри з DirectX 12. Старіший ReShade не завантажує аддони ZoneSDK. |
| Вкладка аддона не з'являється в грі | Виконайте `.\doctor.cmd -Addon MyHud`. `MyHud is disabled in ReShade.ini`: увімкніть його на вкладці Add-ons у ReShade. `ReShade.ini AddonPath=`: ReShade шукає аддони в іншій теці. Інакше перевірте версію ReShade (вище) і тег (нижче). |
| Із двох аддонів один ніколи не завантажується | У них спільний тег. Переглядач налагоджувального виводу на кшталт DebugView показує `ZoneSDK: <name> does not load: the tag <tag> is already taken ...`. Дайте одному з них інший тег і зберіть наново. |
| Вкладка показує «Частини аддона MyHud вимкнено після помилки: <частини>. Подробиці в журналі.» | Структурований виняток (наприклад, порушення доступу) стався у вкладці, під час запуску аддона або в основній роботі SDK. Тоді власну вкладку аддона заступає цей текст, шлях до журналу і кнопки **Спробувати ще** та **Скопіювати звіт**. Збій в іншій частині (наприклад, у `frame` чи в хуку GPU) вкладку не змінює, а «Діагностика» показує `present.<lane>` у рядку «Вимкнено після збою». В обох випадках у журналі є один рядок `structured exception 0x... at <module>+0x... in the <lane> lane, ...`; з pdb цієї збірки (крок 8) налагоджувач показує функцію і рядок для зсуву `MyHud.addon64+0x...`. Виправте код і зберіть наново, потім натисніть «Спробувати ще». Див. [RULES-UA.md](RULES-UA.md#55-коли-щось-падає). |
| «Діагностика» показує «Версія гри: <12 шістнадцяткових цифр> (інша)» або doctor пише `game build ... is unknown` | Гру оновили або це не одна зі збірок Steam, які знає ZoneSDK (`doctor.cmd` їх перелічує). Аддон запускається, але функції, прив'язані до відомої збірки, лишаються вимкненими. Див. [PATCH_DAY-UA.md](PATCH_DAY-UA.md). |
| Підказка «Ця версія гри не підтримується, аддон нічого не змінює» | Файл гри — не Steam-збірка (наприклад, Game Pass), або оновлення гри так змінило exe, що ZoneSDK не знаходить у ньому рушія. ZoneSDK 1.0.2 підтримує лише версію для Steam; про оновлення гри див. [PATCH_DAY-UA.md](PATCH_DAY-UA.md). |
| fakehost: `a process named Stalker2-Win64-Shipping is running (the game or another fake host); the fake host does not start next to it, ...` | Спершу закрийте гру. Інший прогін несправжнього хоста (наприклад, `-Verify` у другому вікні) теж заважає, бо несправжній хост має ту саму назву: дочекайтеся, поки він закінчиться. |
| fakehost: одна перевірка один раз провалюється, а потім проходить | Деякі перевірки міряють час. На завантаженому ПК закрийте важкі програми і запустіть ще раз. Провал, що повторюється, — справжня проблема. |
| `verify: FAIL the binary contains an absolute path: ...` | Ваш код кладе у файл теку з вашого ПК, наприклад через `__FILE__` або записаний у коді шлях. Приберіть його. |
| `refused: ... is a Debug build ...` | Зберіть і запакуйте збірку Release: `.\build.cmd -Tests`, потім `.\pack.cmd`. |
| pack: `WARNING: ... was not built with passing tests (build.cmd -Tests or test.cmd): pack.cmd -Build tests it first` | Останнє збирання `bin\MyHud.addon64` пройшло без `-Tests`. Зберіть командою `.\build.cmd -Tests` (або скористайтеся `.\pack.cmd -Build`) і запакуйте знову. |
| pack: `dist\README-EN.txt needs {{AUTHOR}}, but it is empty ...` | Аддон створено без `-Author`. Задайте `MYHUD_AUTHOR` у `src\version.h` і зберіть наново. |
